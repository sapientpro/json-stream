# 3.0 API and migration

The parser consumes one JSON or JSON5 document incrementally. Parsing and callbacks
run synchronously inside `write()`. Call `end()` to validate EOF and complete
consumers. No document-sized `JSON.parse` call or token object stream is involved.

```ts
import {createParser, Any} from '@sapientpro/json-stream';
const parser = createParser({format: 'json', retainRoot: false});
parser.onValue(['items', Any, 'id'], (value, path) => {
  console.log(value, path); // e.g. 42, ['items', 0, 'id']
});
parser.write('{"items":[{"id":42}]}');
parser.end();
```

## Values and retention

`new JsonParser(options)` uses strict JSON. `new Json5Parser(options)` uses JSON5.
`createParser({format: 'json5', ...options})` chooses the scanner once.

By default `retainRoot: true` builds the complete value, available as `root` when
`rootReady` is true. `finished` becomes true only after successful `end()`, including
trailing whitespace/comment validation. A callback may receive a value before
later input invalidates the document; delivery is not transactional.

With `retainRoot: false`, only values required by active value consumers and their
retained ancestors are built. `root` stays undefined. A subscription to `[]`
necessarily builds the complete document even with retention disabled. String
consumers alone do not retain the complete string. The selector trie and transition
cache are bounded by registered selectors, not by distinct input property names.

Register every consumer before the first `write()` (including an empty write).
Unsubscribe at any time. Late subscriptions and completed-value replay are not
supported, including after a reset. `getValue(path = [])` returns a promise for the first matching value;
it rejects on parser failure or if no value matched at document completion.

`onValue(path, callback)` and `onString(path, callback)` return `{unsubscribe()}`.
A callback receives `(value, path)` directly. The concrete path is an owned snapshot
which can be stored beyond the callback. Treat it as immutable: overlapping
consumers may share the same snapshot. Alternatively pass an observer object:

```ts
parser.onValue(['items', Any], {
  next(value, path) {},
  error(error) {},
  complete() {},
});
```

A consumer exception does not interrupt parser delivery. Set `onObserverError`
to handle it; otherwise it is rethrown in a microtask. `write()` and `end()` cannot
be called recursively from a callback. `destroy()` can stop parsing from a callback.
`destroy(error)` fails consumers; `destroy()` closes them without successful EOF.

## Paths and JSONPath

Direct paths distinguish array indexes from object properties: `[0]` matches an
array element and `['0']` an object property. `Any` matches one property or array
index. A terminal `Rest` matches all descendants, at least one level below the
preceding path. Dotted strings remain shorthand for property paths; use arrays
for literal dots, indexes or wildcards. `[]` denotes the document root.

`compileJsonPath(query)` compiles the supported RFC 9535 child-selector subset
once to a frozen direct path. The convenience methods are
`onValueJsonPath(query, callback)`, `onStringJsonPath(query, callback)` and
`getValueJsonPath(query)`.

Supported: `$`, `.name`, `['name']`, `["name"]`, nonnegative safe integer indexes
such as `[0]`, and wildcard `.*`/`[*]`. Quoted names support JSONPath escapes and
Unicode scalar characters. Numeric index selectors match arrays only; quoted
numeric names match objects only.

Recursive descent, negative indexes, unions, slices and filters are explicitly
rejected with `SyntaxError`. This is a documented subset, not a complete JSONPath
implementation. Direct `Rest` has its own semantics and is not exposed as `..`.

## Streaming strings and pacing

```ts
parser.onString(['items', Any, 'text'], {
  next(fragment, path) {},
  end(path) {}, // once for each matched string, including empty strings
  complete() {}, // once at document EOF
});
```

Fragments are decoded text. Boundaries depend on input chunks and escapes; a
surrogate pair is kept together across chunk cuts. Invalid lone escaped surrogates
accepted by JSON can still appear as lone units. No empty fragment is emitted.
`end(path)` separates strings when a selector matches multiple values.

`stringStream(path)` exposes fragments as a Web `ReadableStream`. It concatenates
matches without boundary markers; use callbacks if per-string boundaries matter.
Canceling it unsubscribes that consumer while parsing can continue.
`maxBufferedChunks` limits its pending fragment queue (default `Infinity`);
overflow errors that stream and unsubscribes it. This is a queue bound, not parser
backpressure.

The caller controls input pacing. Async callback return values are not awaited.
The parser completes each write synchronously, so a single write can produce many
values. Web/Node writable backpressure regulates input writes, but does not wait
for independent asynchronous value consumers. If those consumers need pacing,
queue their work and control when the next input chunk is fed.

## Transports

Feed text or UTF-8 `Uint8Array`/Node `Buffer` chunks. Choose one input mode per
parser; mixing text and byte chunks throws before consuming the mixed chunk.
Byte decoding is incremental and flushes at `end()`.

```ts
await response.body!.pipeTo(parser.writable);
// Or createWritableStream(parser) for an explicit sink.
```

Node adapters live in `@sapientpro/json-stream/node`:

```ts
import {JsonStream, createNodeWritable} from '@sapientpro/json-stream/node';
import {pipeline} from 'node:stream/promises';
const stream = new JsonStream({format: 'json5'});
const result = stream.getValue(['settings']); // register first
await pipeline(source, stream);
console.log(await result);
```

`createNodeWritable(parser)` wraps an existing core parser. `JsonStream` also
forwards the callback/value/string APIs and emits `value` once when root becomes
available. `parsed` reflects successful EOF. With retention disabled its `value`
event has an undefined root; use value callbacks to retrieve selected values.
Node adapters preserve string chunks rather than silently converting them to
bytes; do not mix strings and Buffers on the same parser.

## Migration from 2.x

| 2.x | 3.0 |
| --- | --- |
| `observe(path).subscribe(({value, path}) => ...)` | `onValue(path, (value, path) => ...)` |
| `chunks(path).subscribe(fragment => ...)` | `onString(path, (fragment, path) => ...)` |
| `value(path)` | `getValue(path)` |
| `stream(path)` | `stringStream(path)` |
| numeric-string selectors accepted on arrays | numeric indexes require numbers |
| late registration with root retention/replay | register before first write; no replay |
| root completion used as `finished` | `rootReady` for availability; `finished` after `end()` |
| permissive syntax in some JSON cases | strict separators, escaping, numbers and trailing input |

`collectJson`, `maxDepth` and `retainRoot` remain options. `start` moves to an optional input manager; the core accepts only JSON/JSON5. `collectJson`
retains all decoded input and therefore defeats bounded input-memory usage.
`maxDepth` defaults to 1000 and accepts nonnegative safe integers or Infinity.
A core parser consumes one document. Optional managers below consume multiple documents.


## Reusing a core parser

`reset()` validates the current document exactly as EOF would, then clears its
value, string/number/comment state and per-document input while preserving active
subscriptions and cached selector transitions. It does not emit consumer completion.
Use it **instead of `end()` at intermediate document boundaries**; call `end()`
only for the final document. An incomplete or invalid document fails rather than
being discarded. A closed/failed parser cannot reset. Registration stays frozen
and the input mode stays fixed across resets. Canceled consumers stay canceled.
`getValue` remains a first-match promise, not a promise reused for every record.

```ts
const parser = new JsonParser();
parser.onValue([], value => console.log(value));
parser.write('1');
parser.reset(); // validates and emits 1, keeps the subscription
parser.write('{"second":true}');
parser.end();  // emits second value, completes the input
```

`root`, `rootReady`, `finished` and collected `json` are cleared by reset.
Previously delivered objects and owned paths remain valid. JSONL and prefix
managers call reset internally; their consumer completion still means whole-input
EOF.

## JSON Lines and prefixed documents

```ts
import {JsonLinesParser, PrefixedJsonParser, Any} from '@sapientpro/json-stream';

const lines = new JsonLinesParser({retainRoot: false});
lines.onValue(['items', Any, 'id'], (value, path, recordIndex) => {});
lines.onString(['text'], {
  next(fragment, path, recordIndex) {},
  end(path, recordIndex) {}, // one matched string
  complete() {},           // whole input, not each record
  error(error) {},
});
lines.write('{"text":"first"}\n{"text":"second"}\n');
lines.end();

const prefixed = new PrefixedJsonParser('data:', {format: 'json5'});
prefixed.onRecord((value, recordIndex) => console.log(value, recordIndex));
prefixed.write("noise data:{key:'first'} trailer data:{key:'second'}");
prefixed.end();
```

Both managers reuse one core parser and its subscriptions across records. They accept text or UTF-8 bytes and expose `write`, `end`, `destroy`,
`writable`, `closed`, `finished` and `recordCount`. `createNodeWritable(manager)`
provides the Node sink. Paths remain relative to each document; the zero-based
record index is a separate callback argument. Register before the first write.
Unsubscription persists across later records. Errors fail the whole input;
observer `error`/`complete` fires once for the input. Each matched string has its
own `end(path, recordIndex)`. A root subscription via `onRecord` retains that
record even with `retainRoot: false`. Values are delivered when structurally
complete, before later record validation; delivery is not transactional.
`recordCount` counts successfully ended documents. Previous roots are not retained
by the manager. `getValue(path)`/`getValueJsonPath(query)` returns the first match
across records; missing values reject at input EOF. `stringStream(path)` concatenates
matched strings across records and closes at input EOF. Cancellation/queue bounds
behave like the single-document string stream.

`JsonLinesParser` defaults to strict JSON. LF ends each record; CRLF works, and the
last record may omit LF. Blank records, an initial BOM and malformed/truncated UTF-8 byte input fail. Empty input means
zero records. An explicit `{format: 'json5'}` is a nonstandard JSON5 Lines extension:
**each record must occupy one physical line**. Multiline comments, actual line
continuations and pretty-printed multiline structures are unsupported; escaped
`\n` is allowed. LF always terminates a record, regardless of JSON5 lexical state.
Fragments are forwarded immediately, without buffering whole lines.

`PrefixedJsonParser` seeks the exact marker before every document. The scanner
stops at the root boundary and gives the unconsumed input back to the manager;
there is no second grammar scanner. Before the root finishes, a marker inside
strings, nested containers or JSON5 comments cannot split a document. Trailing
comments/noise after the completed root are outside the record and participate
in the next marker search. Multiline JSON and JSON5 work here.
For scalar tokens, use whitespace between the value and the next marker to avoid
ambiguity with a continuing number/literal. EOF also terminates a valid scalar.
Input outside documents is ignored while seeking the next marker. No marker at all
or a final marker without a complete value fails; unmatched trailing noise is ignored.
The seeking buffer holds at most `marker.length - 1` UTF-16 units between writes.
This is marker framing, not an SSE protocol implementation.

For one payload, `new PrefixFilter(parser, marker)` is the lower-level input filter.
It discards input through the first marker and forwards the rest to an existing
parser or manager. Register consumers on that target before feeding the filter.
`collectJson` and syntax offsets on the target refer to the forwarded payload;
transport-prefix offset mapping is not supplied.
